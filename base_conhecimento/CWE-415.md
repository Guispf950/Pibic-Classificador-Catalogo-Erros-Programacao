# CWE-415 — Liberação Dupla (Double Free)

## O que é
Acontece quando o programa chama `free()` **duas vezes** sobre o mesmo bloco de memória.
A primeira liberação é correta; a segunda tenta devolver ao alocador algo que já não
pertence mais ao programa, corrompendo as estruturas internas do gerenciador de memória.

## Por que acontece em C
Depois de `free(p)`, o ponteiro `p` continua com o mesmo endereço (vira um *ponteiro
pendente*). Se esse mesmo ponteiro — ou outro que aponte para o mesmo bloco — for liberado
de novo, ocorre o double-free. Em iniciantes, é comum quando dois ponteiros apontam para o
mesmo nó e ambos são liberados, ou quando um `free` aparece dentro de um laço/condição que
executa mais de uma vez para o mesmo bloco.

## Como interpretar o que a ferramenta apontou
A ferramenta indica o ponto da **segunda** liberação (o sintoma) e, quando disponível, o
ponto onde o bloco foi **alocado** e onde foi **liberado da primeira vez**. O erro está na
existência de duas liberações para a mesma memória, não numa liberação isolada.

## Princípio da correção (sem código)
A ideia é garantir que cada bloco seja liberado **uma única vez**. Isso passa por ter clareza
de qual parte do código é "dona" de cada alocação (responsável por liberá-la) e por evitar
que dois caminhos liberem o mesmo bloco. Marcar um ponteiro como inválido logo após liberá-lo
ajuda a detectar uma segunda liberação acidental.
