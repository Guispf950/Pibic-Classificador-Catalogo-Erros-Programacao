# CWE-590 — Liberação de Memória Fora do Heap (Free of Memory not on the Heap)

## O que é
Acontece quando o programa chama `free()` sobre um endereço que **não foi obtido por uma
alocação dinâmica** (`malloc`/`calloc`/`realloc`). Só memória vinda do heap pode ser
liberada; passar qualquer outro endereço para `free()` corrompe o alocador.

## Por que acontece em C
Em C é fácil obter um ponteiro para algo que não é do heap: o endereço de uma variável local
(`&x`), o endereço de um elemento de um vetor, ou um ponteiro que foi movido para o **meio**
de um bloco (ex.: `p++` e depois `free(p)`). Como `free()` espera exatamente o endereço que
`malloc()` devolveu, qualquer um desses casos é inválido.

## Como interpretar o que a ferramenta apontou
A ferramenta aponta a chamada de `free()` problemática (o sintoma). A causa é a **origem do
ponteiro**: ele não veio de uma alocação dinâmica, ou não aponta mais para o início do bloco.

## Princípio da correção (sem código)
Só passe para `free()` um ponteiro que veio **diretamente** de um `malloc`/`calloc`/`realloc`
e que **ainda aponta para o início** do bloco. Nunca libere endereços de variáveis locais ou
globais, nem ponteiros que foram avançados. Se você precisa percorrer um bloco com um ponteiro
auxiliar, guarde à parte o ponteiro original (o do `malloc`) para liberar depois.
